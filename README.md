# My Listening Top 9

Локальный прототип на Next.js 16 / TypeScript / React. Без демонстрационных результатов. Проверка документации: 18 октября 2026.

## Запуск

Нужен Node.js >= 20.9 (рекомендуется 24 LTS). Системный Node 16 на этой машине слишком старый.

```powershell
npm install
Copy-Item .env.example .env.local
# Внести SPOTIFY_CLIENT_ID в .env.local
npm run dev
```

Открыть http://127.0.0.1:3000 (именно 127.0.0.1). Импорт работает без Client ID.

Проверки: `npm test`, `npm run typecheck`, `npm run build`. Production: `npm run build`, затем `npm start`. После изменения env перезапустить сервер.

## Spotify: подключение и реальная проверка

1. Открыть https://developer.spotify.com/dashboard и создать Web API app. Владелец должен иметь Premium.
2. Redirect URI: `http://127.0.0.1:3000/api/auth/spotify/callback`.
3. Settings → Users Management: добавить тестовый аккаунт (до 5 пользователей).
4. Записать Client ID в `.env.local`. Client Secret не нужен: Authorization Code + PKCE S256. Никогда не передавать пароли/cookies.
5. Перезапустить сервер, нажать «Подключить», пройти согласие Spotify самостоятельно.
6. Нажать «Проверить реальные API-запросы»: проверяются `/me`, `/me/top/tracks`, `/me/player/recently-played`. Отчёт содержит только результат запроса и количество элементов, без токенов и истории. Затем «Собрать мой Top 9» для каждого окна.

Реальная проверка аккаунта **ещё не выполнена**: Client ID и OAuth-согласие не предоставлены. Наличие кода не доказывает доступность данных конкретного аккаунта. 403 и 429 показываются явно.

## Что реализовано

- Spotify OAuth PKCE, refresh, серверная сессия; приблизительный Top 9 по первым 50 top tracks. Статус: реализация готова, реальный аккаунт не проверен.
- Локальный импорт нескольких Spotify Extended Streaming History JSON, фильтр дат UTC, сортировка по `ms_played` или событиям. Статус: проверено синтетическими наборами с известными ответами.
- Takeout JSON: аудит истории, разделение явных `music.youtube.com`, обычных YouTube и неопределённых. Альбомный рейтинг не создаётся без надёжных метаданных.
- Три темы; PNG 1080×1080 и 1080×1920, до 9 фактических альбомов. Экспорт без обложек использует явно условные номера. Файлы экспорта не содержат минут/чисел из приблизительного рейтинга.
- Deezer: отдельный адаптер статуса, без неработающей OAuth-кнопки.

## Правила подсчёта

Приблизительно: N — число возвращённых треков (не более 50), позиция r начинается с 1. Вес = N − r + 1. Сумма весов по album ID, затем убывание суммы, при равенстве лексикографический ID. Повторный track ID игнорируется. Это индекс предпочтения, не оценка реального числа plays/минут. Все типы релизов (album, single, compilation) включены; издания с разными ID отдельны. Названия не нормализуются.

Импорт: точный дубль всей строки (ключи отсортированы) удаляется между файлами; разные timestamp/device/metadata остаются разными событиями. Нулевая длительность, подкасты, неизвестные альбом/исполнитель исключаются. Положительная длительность любого размера считается событием, без порога «полного прослушивания». Даты включительны, UTC. Время берётся только из `ms_played`, не из длительности трека. Синглы, сборники, deluxe и переиздания с разным названием не объединяются. Нет album ID: точная пара artist+album, совпадающие пары разных изданий неразличимы. Это ограничение явно указано. Рейтинг «точно в файлах» означает точный подсчёт этих групп; полноту архива подтверждает пользователь, независимо она не доказана. Без подтверждения — частичная история. Точный рейтинг по полной истории с гарантированной идентичностью релизов не обещается.

Takeout: категория Music или слова в заголовке не доказывают музыкальное прослушивание. Явный hostname music.youtube.com — свидетельство источника, но не album ID и не время прослушивания. Не используем длину видео как время пользователя. HTML/ZIP Takeout не поддерживаются: запросить JSON и распаковать. Неразрешённые записи не попадают в Top 9.

## Приватность

Импорт читается только браузером, не хранится в localStorage/IndexedDB и не загружается на сервер. Токены только в памяти Node, случайный идентификатор сессии в HttpOnly SameSite=Lax cookie, максимум 24 часа; OAuth state одноразовый, 10 минут. Перезапуск сбрасывает сессии. Отключение удаляет серверную сессию, токены и состояние импорта в UI; загруженные исходные файлы на диске пользователя не удаляются. Для отзыва согласия Spotify: https://www.spotify.com/account/apps/. Уже скачанные PNG пользователь удаляет самостоятельно. Несколько открытых вкладок могут сохранять результат в своей памяти до закрытия/перезагрузки.

Сервер слушает только loopback. Это не production SaaS: перед публичным запуском нужны разрешение сервиса, durable encrypted sessions, распределённые квоты, privacy policy и проверки экспорта обложек/атрибуции. API cover допускает только HTTPS i.scdn.co/image/, без редиректов. Не добавлять токены, экспорт истории, `.env.local` в Git. Не включать access-логи query callback на внешнем reverse proxy. Приложение не печатает историю или токены в логи.
